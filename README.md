# TYCPHIGROS4.0.1.2

本轮更新 `4.0.1.2-input-8`，重点处理快速双指吃键、慢网首次加载及声音/谱面不同步。

每次实际按下保留独立、最多 128 条的输入记录。PointerEvent 与 TouchEvent 按捕获时间、起点和生命周期关联，同一入口的新按下不按位置合并；即使另一入口晚到、原触点已抬起或系统复用编号，也不会把旧快照重建为新点击。移动接管保留原按下标记、噪域状态及 Hold/Drag/Flick 所有权。回归包含 1,200 组快速双指交错、入口延迟、缺项和编号复用，以及连续 300 次点击的记录容量检查。

设置中的“输入与帧率详情”可直接打开/关闭诊断，无需外接键盘；显示当前版本、合并后的点按接收、两个入口各自的原始按下数、蓝键/长条命中、缓冲中按下、媒体时钟差及实际帧耗时。两个原始入口可能各收到同一根手指的一次按下，不能相加作为实际点按数。诊断默认关闭。暂停、结算和打开面板时立即刷新当前计数，不等待下一次动画帧，也不添加或伪造 FPS 样本。

前置黄键/红键不再否决正常 Perfect/Good 蓝键；早 Bad 防误触仍保留，备用 Hold 查询使用同一个输入时间。真实抬手清理触点映射，允许快速复用触摸编号。

输入保留原始事件时间戳，兼容 epoch 时间戳并处理无效的零/未来时间；捕获时间换算扣除网络缓冲的冻结区间，避免缓冲几秒就把排队输入错误换算到几秒以前。冻结前捕获的有效点击仍可按原窗口判定，冻结期间的点击不会在恢复后命中未来音符。主线程卡顿后，Tap/Hold 的 Miss 最终结算留出 48ms 输入派发机会；Perfect/Good/Bad 窗口不变，真正迟点和没有点仍判 Miss。

绘制不设置 60fps 定时器门槛，逐次跟随浏览器 requestAnimationFrame；已探测到的 120Hz 节奏保留 8.33ms 工作预算，单次掉帧不把预算降为 60Hz。面板报告实际回调频率，慢帧和超过 1 秒的停顿均计入；不把 110Hz 吸附显示为 120Hz，绘制预算单独保留已测得的稳定节奏。网页不能强制 Safari/系统提供持续 120Hz，真机持续帧率仍需验证。

本次更新：按提供的录屏加入厂商标识、阅读提示、模糊渐清的标题开场、动态粒子和三角网格；使用录屏提取的循环音乐，以音频时钟切换画面。标题版本与录屏一致，为 4.0.1.2。iPad Safari 若禁止首次有声自动播放，可点右下角“点按开启音乐”。点击标题页进入章节时停止开场音乐。

选歌使用“小图 → 中图 → 高清图”的独立渐进资源。游玩背景在加载阶段选取可用的中图，最多额外等待 350ms，随后固定到本局结束；不在音符出现后启动高清解码、磨砂处理或替换背景。画布按完整帧合成显示，避免前缓冲撕裂和清空图片造成的闪屏。

内置歌曲通过同站 AAC/M4A 原生流式播放。音频缓冲、谱面下载与解码、皮肤和字体同时准备；加载谱面不等待可选封面。正常连接目标约 6–8 秒，慢连接目标最多 12 秒，不再按整首剩余时长要求预载大半首音乐。若移动浏览器的暂停预载停在至少 6 秒且已可播放，短暂确认后允许开始，避免一直等浏览器不再提供的额外缓冲。加载页显示实际缓冲量，并可返回选歌。

媒体确实不可播放时立即冻结谱面；短暂恢复不进入手动暂停或重新倒数。持续断流按 6–12 秒目标补缓冲，从原媒体位置继续，保留长按和正常松手。时钟不再保留已经超前的预测值；停播、跳转和明显偏差回到真实媒体时间，正常帧插值上限为媒体时间前方 25ms。缓冲冻结期间继续跟踪触点并重置运动采样，避免恢复时把冻结时间算成手指松开或谱面时间。主动暂停和退出取消自动恢复。后台并行处理减少等待与主线程负担，但不能增加网络实际带宽；网络持续低于音乐所需流量时仍可能缓冲。

46 个难度的谱面已拆成单独的压缩文件。原始 OGG、PNG、压缩谱面包和皮肤 ZIP 继续用于完整谱面与视频导出。默认播放不再等待整首音频下载和 Web Audio 全量解码。流式播放的 AAC 由原始音频转码，导出仍读取原始音轨。

性能更新（`input-8`）：谱面由一次性 Worker 自行下载、收集数据、LZMA 解压和 P9C1 结构解码，减少主线程数据搬运；支持进度、取消、超时和 Worker 不可用时的兼容回退。噪域纹理准备使用最多 3 个并行任务。封面缩略图与评级图片使用独立文件、列表按可见范围加载；说明、来源清单与完整许可证放入 `assets/meta/`、`assets/licenses/`。原始皮肤跳过无用的整图像素回读；启动设置用一次数据库读取，字体就绪不阻塞选歌。离开标题时释放开场音轨，取消未选中封面请求，让带宽优先供给当前歌曲。解码资源和谱面记录使用有容量上限的 LRU 缓存。

游玩输入只重算正在查询的判定线及其父线，不再让每个触摸样本重算全部判定线；绘制缓存与输入缓存独立。画布在开歌前按设备设置固定像素预算，逻辑尺寸、触摸坐标、音符数量和判定窗口不变。视频导出继续使用指定的输出分辨率。

## 上传 GitHub 并发布

1. 解压本 ZIP。打开文件夹，应该直接看到 `index.html`、`assets`、`css`、`js`、`workers` 和本说明。
2. 登录 <https://github.com>，打开 <https://github.com/new>。
3. 仓库名称填写 `phi-sekai`，选择 **Public**，勾选 **Add README**，点击 **Create repository**。
4. 进入仓库的 **Code** 页面，选择 **Add file → Upload files**。
5. 上传解压后的项目内容，保持所有子文件夹的原有层级。不要只上传 ZIP，也不要额外套一层项目文件夹。应在仓库首页直接看到 `index.html`。
6. 点击 **Commit changes**。如果显示超过上传数量限制，可以分两次上传 `assets` 和其余文件，保持路径不变。
7. 在仓库进入 **Settings → Pages**，将 **Source** 设为 **Deploy from a branch**，**Branch** 设为 **main**，文件夹设为 **/ (root)**，点击 **Save**。
8. 等待部署完成，在 Pages 中点击 **Visit site**。项目网址一般为 `https://你的用户名.github.io/phi-sekai/`。
9. 学校电脑打开这个 Pages 网址即可；仓库地址是代码管理页，不能代替游戏网址。学校网络是否允许访问，需要现场测试。

GitHub 网页上传限制是每个文件 25 MiB。本项目的所有文件均低于该限制；上传前不需要再次压缩或拆分。

如果已经授权 ChatGPT 的 GitHub 插件访问该仓库，可以把仓库链接发给 ChatGPT，继续上传项目。当前插件如果没有 Pages 设置接口，首次启用 Pages 仍需要按第 7 步手动完成。

## 本地预览

多文件版需要通过 HTTP/HTTPS 访问，直接双击 `index.html` 的 file:// 方式不能正常加载资源。

电脑安装 Python 后，在项目文件夹打开终端并运行：

```sh
python -m http.server 8000
```

然后访问 <http://localhost:8000/>。

## 修改与更新

- 改界面文字或结构：修改 `index.html`。
- 改外观：修改 `css` 中的样式。
- 改游戏逻辑：修改 `js/app.js`，保留引用路径。
- 更新完成后上传同路径的文件并提交，Pages 会重新发布。
- `assets/charts/*.bin` 保留原文件的压缩谱面格式，不能作为普通文本直接编辑；可使用游戏原有的谱面导入功能。
- 音乐和曲绘保持原始数据，没有重新编码或降低清晰度。
- 存档、导入谱面和已保存视频仍使用原有浏览器本地存储。换设备不会自动同步这些本地数据。
- 原 HTML 的授权及来源说明已保留。拆分本身没有改变资源的授权状态。
